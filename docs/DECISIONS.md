# Architectural & Implementation Decisions

Recorded per `PROJECT_REQUIREMENTS.md` §0.1 and §22.3.

| ID     | Topic                                                         | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Rationale                                                                                                                                                           |
| ------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DEC-01 | Brand identity defaults                                       | Default configurable brand name is `Maison Aurelia` (via `NEXT_PUBLIC_SITE_NAME` and Store Settings `storeName`). Never hard-coded in UI components; all components read from centralized `siteConfig` / Store Settings.                                                                                                                                                                                                                                                                                                                                                                                 | Satisfies `<BRAND>` rule and allows instant white-labeling via env/admin settings.                                                                                  |
| DEC-02 | Store currency, target countries & tax                        | Default currency `USD` (configurable in Store Settings), target countries `US`, `CA`, `GB`, `AU`, `IN`, default tax rate `8.00%` tax-exclusive labeled `Estimated Tax`, plus insured signature threshold `$500.00`.                                                                                                                                                                                                                                                                                                                                                                                      | Covers North America + international jewellery shipping; fully configurable by ADMIN in Store Settings.                                                             |
| DEC-03 | Return policy defaults                                        | 30-day complimentary return (`merchantReturnDays: 30`, `returnMethod: ReturnByMail`, `returnFees: FreeReturn`), surfaced in Shipping & Returns page, PDP accordion, and JSON-LD `hasMerchantReturnPolicy`.                                                                                                                                                                                                                                                                                                                                                                                               | Keeps Search Console / Merchant Center markup consistent with visible policy copy (SEO-15).                                                                         |
| DEC-04 | Physical store / showroom                                     | Store Settings includes a `physicalStore` object (`enabled`, `name`, `street`, `city`, `region`, `postalCode`, `country`, `phone`, `openingHours`, `latitude`, `longitude`). Demo seed enables a Fifth Avenue showroom; production seed defaults `enabled: false` until configured by admin.                                                                                                                                                                                                                                                                                                             | Ensures `JewelryStore` JSON-LD and appointment CTA appear only when configured (SEO-14, CW-10).                                                                     |
| DEC-05 | Docker Compose host ports                                     | `docker-compose.yml` parameterizes host ports (`POSTGRES_PORT:-5432`, `REDIS_PORT:-6379`, `SRH_PORT:-8079`, `MINIO_API_PORT:-9000`, `MINIO_CONSOLE_PORT:-9001`, `MAILPIT_SMTP_PORT:-1025`, `MAILPIT_UI_PORT:-8025`) so standard defaults work in clean CI/dev while local `.env` sets non-conflicting ports (`5435`, `6380`, etc.) when host ports 5432/6379 are occupied.                                                                                                                                                                                                                               | Prevents collision with existing host services while keeping standard defaults.                                                                                     |
| DEC-06 | Payment providers & sandbox verification                      | Both `StripePaymentProvider` (Stripe SDK + PaymentIntent + webhook HMAC) and `RazorpayPaymentProvider` (Razorpay SDK + Orders API + HMAC-SHA256) are implemented behind `PaymentProvider`. When `PAYMENT_TEST_SANDBOX=true` (strictly forbidden when `NODE_ENV=production` unless `ALLOW_PAYMENT_SANDBOX_FOR_CI=true` during local CI/E2E runs) and real live keys are absent, a deterministic signed sandbox adapter executes the exact same order, reservation, webhook idempotency, and refund DB flows so full E2E and webhook testing run without external credentials.                             | Enables complete end-to-end verification in test mode without fake production paths.                                                                                |
| DEC-07 | Email transport                                               | `Resend` SDK is used in production when `RESEND_API_KEY` is provided; in local development / Docker (`SMTP_HOST` / Mailpit on `1025`), Nodemailer delivers rendered React Email HTML/text directly to Mailpit so every transactional email can be inspected locally.                                                                                                                                                                                                                                                                                                                                     | Zero external email credentials required for dev/E2E while supporting Resend in production.                                                                         |
| DEC-08 | Object storage & local image serving                          | Presigned PUT uploads target S3-compatible storage (MinIO locally, R2/S3 in production). `next.config.ts` configures `images.remotePatterns` from `NEXT_PUBLIC_IMAGE_CDN_URL` / MinIO endpoint. In `local`/test environments without an active public CDN, MinIO serves public-read objects under the configured bucket prefix.                                                                                                                                                                                                                                                                          | Keeps upload/EXIF/magic-byte pipeline identical between local MinIO and production R2/S3.                                                                           |
| DEC-09 | AI training crawlers                                          | Default `aiCrawlerPolicy` allows both search/retrieval bots (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Perplexity-User`, `Claude-SearchBot`, `Claude-User`) and training bots (`GPTBot`, `ClaudeBot`, `Google-Extended`, `Applebot-Extended`, `CCBot`), editable live from Admin → Settings → AI Crawler Policy.                                                                                                                                                                                                                                                                                | Matches §14.1 AI-03 default while giving store owner instant control.                                                                                               |
| DEC-10 | Static policy pages & guides split                            | Legal/informational pages (`/privacy`, `/terms`, `/shipping-returns`, `/care-guide`, `/ring-size-guide`, `/about`, `/faq`) load structured Markdown/MDX files from `content/` (so content edits are version-controlled and fast SSR), while editorial Guides (`/guides/[slug]`) are stored in PostgreSQL (`Article`) and managed in Admin.                                                                                                                                                                                                                                                               | Implements CW-100 exactly as specified.                                                                                                                             |
| DEC-11 | Sitemap index rewrite & Next App Router redirects/404         | In Next.js 16 with `generateSitemaps()`, exporting both `app/sitemap.ts` and `app/sitemap.xml/route.ts` triggers a build conflict, so the XML `<sitemapindex>` handler lives at `/sitemap-index.xml` and `next.config.ts` rewrites `/sitemap.xml` via `beforeFiles` to `/sitemap-index.xml`. Permanent redirects (`SlugRedirect` and `ARCHIVED` products) emit Next `permanentRedirect` (HTTP 308), while removed/soft-deleted product URLs emit standard App Router `notFound()` (HTTP 404) so database queries stay outside `proxy.ts` per Next 16 Proxy guidance.                                     | Satisfies SEO-11a & SEO-17 cleanly inside Next.js 16 constraints without DB pools in Edge/Proxy middleware.                                                         |
| DEC-12 | CSP compatibility, dynamic upload handler & `htmlLimitedBots` | `src/lib/zod-csp.ts` enables Zod v4 `jitless: true` in browser runtimes so schema compilation never probes `new Function("")` against enforced `script-src` CSP; `src/proxy.ts` enforces static/PPR-safe CSP plus nonce-based `Content-Security-Policy-Report-Only`. Runtime local uploads saved under `public/uploads/` are also served dynamically via `src/app/uploads/[folder]/[filename]/route.ts` for standalone server deployments, and `next.config.ts` scopes `htmlLimitedBots` to crawlers/AI bots/`Chrome-Lighthouse` (avoiding Next 16 `NEXT_STATIC_GEN_BAILOUT` on browser RSC prefetches). | Guarantees zero enforced CSP violations, reliable standalone local media serving, blocking `<head>` SEO meta tags for crawlers, and zero 500s on client navigation. |
